가설: 삭제 후 품질을 만족하는 후보 중 실제 삭제 통신비가 작은 shard 배정을 선택할 수 있다 | 독립변수: 균등 random/channel/data 배정 | 종속변수: 초기·삭제 학습 완료율, 평균·최악 삭제 UL | 통제: 같은 N20/K4/크기5/학습 완료 규칙 | 상태: 선택 코드 구현, 첫 seed의 후보 평가 완료; 전체 18조건 중 10조건 완료, 나머지 GPU 대기

목표
데이터와 채널을 입력으로 사용하되, 최종 선택은 실제 삭제 후 재학습 비용으로 한다. 삭제확률 예측은 사용하지 않는다. 향후 정확도, 완료율, 준비비용, 통신비의 절충을 비교할 수 있게 만드는 기준 알고리즘이다. 새로운 저비용 배정 방법의 우월성을 이미 입증했다는 뜻은 아니다.

입력
- 클라이언트별 허용된 클래스 count/데이터 수와 장기 채널 크기.
- 고정 shard 수 K, shard당 크기, 송신 전력과 라운드 무선 예산.
- 공개 검증셋, shard별 목표 정확도 a, 최대 라운드 L.
- 이번 실험: N20, K4, 각5명, a=.65(primary) 또는 .60(별도 민감도), L200.

학습 완료 규칙
각 shard가 자신의 모델을 공개 검증셋으로 20라운드마다 평가한다. 연속 두 번 a 이상인 최초 라운드 T에서 완료한다. 초기학습과 삭제재학습에 같은 규칙을 적용한다. 앙상블 전체 정확도로 개별 shard의 중단을 결정하지 않는다. L 안에 못 넘으면 해당 품질 조건에서 미완료로 표시한다. 이것은 SISA의 삭제 독립성이 깨졌다는 판정이 아니다.

목적함수
J(P) = (D/N) * sum_u T_u(P), D=38,282 parameters.
T_u는 u가 속한 shard에서 u를 제외하고 초기화부터 같은 규칙으로 재학습한 완료 라운드다. 완료하지 못한 요청의 비용을 L라운드 완료로 대체하지 않는다.
제약: 모든 source shard가 완료하고, 평가한 모든 client 삭제가 완료해야 후보가 가능하다. 실제 test 정확도는 선택에 사용하지 않고, 선택 후 품질·비용 trade-off를 보고한다. 각 shard에 높은 목표를 요구하면 앙상블 품질만 요구할 때보다 보수적일 수 있다.

구체적 절차
1. 같은 크기의 random, channel, data 후보를 만든다.
   channel은 평균 1/(n² hmin²), data는 평균 클래스 JS를 줄인다. 두 후보 모두 같은 시작점 두 개와 client pair 교환을 사용하고 최대15번 개선한다. 전역 최적해라고 주장하지 않는다.
2. 각 후보의 source shard들을 독립적으로 학습하고 완료 여부를 기록한다.
3. 각 client를 하나씩 가상 삭제하여 해당 shard만 재학습한다. 남은 클라이언트는 4명이고, 다른 shard의 모델은 그대로 둔다. 모든 요청은 원래 source에서 독립적으로 평가한다.
4. 품질 조건을 만족하는 후보 중 실제 평균 삭제 UL이 최소인 후보를 선택한다. 동률이면 최악 삭제 UL, source UL 순서로 비교한다.
5. 선택된 배정을 최종 학습 전에 고정한다. 서버는 shard별 초기화와 모델을 저장하고, 실제 삭제 요청 때 해당 shard만 재학습한다. 모든 client가 처음부터 참여했으므로 안전한 rollback은 초기화다.
6. 가능한 후보가 없으면 no_feasible_candidate를 반환한다. 목표 정확도를 결과에 맞춰 자동으로 낮추지 않는다. 낮은 목표나 큰 L은 별도의 조건으로 보고한다.

현재 확인한 첫 seed의 사례 (전체 결과 아님)
nominal20dB, a=.60: channel/data 모두20삭제 완료. 평균 round는 channel156, data142. UL은5,971,992 대5,436,044 real uses로 data가8.97% 작다. random은18/20만 완료했다.
a=.65: channel14/20, data18/20, random12/20으로 전체 요청을 충족하는 후보가 없었다.
따라서 같은 데이터에서도 품질 목표를 명시하지 않고 가장 좋은 배정을 하나로 정할 수 없다.

준비 비용과 미검증 부분
이 구현은 후보3개의 source 학습과 각client삭제를 먼저 실행한다. 첫 seed a=.60의 프로파일링 UL합계는409,617,400 real uses다. 후보선택 뒤의 삭제 비용이 줄어도 이 준비비용까지 상쇄하는 순절감은 확인되지 않았다. 연구 계측은 궤적을200까지 실행하므로 실제 실험 비용은 조기중단 가정의 준비비용보다 더 크다.
실용적인 다음 구현에서는 이 실측값으로 비용 예측의 신뢰성을 먼저 확인하고, 영향을 받는 두 shard만 평가하는 이동·교환 탐색과 그룹별 비용 캐시로 평가 횟수를 줄일 수 있다. 이 개선은 이번 실행에서 성능을 확인하지 않았다. JS+MSE 가중합을 검증 없이 실제 삭제 비용이라고 부르지 않는다.

보장과 정보 조건
고정 routing과 공개 검증셋을 조건으로 독립 shard 학습 규칙의 모델 재현을 확인한다. 데이터에 의존한 routing/metadata 자체의 삭제나 무조건적 exact-unlearning 증명과 구분한다. 클래스 count, 데이터 수, 채널 크기의 초기 보고는7680bit/seed로 계산한다. 개별 과거 update 이력은 수집하지 않는다. AirComp만으로 DP나 암호학적 secure aggregation을 보장한다고 주장하지 않는다.
